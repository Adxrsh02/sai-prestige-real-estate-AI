Only publish services that Sai Prestige actually provides. The descriptions below are proposed content and should be aligned with the business's real operating model.

Help clients define their requirements for apartments, flats, and homes by considering budget, preferred location, configuration, connectivity, amenities, possession status, maintenance, and documentation. Property availability and suitability must be confirmed for each enquiry.

Mention this service only if Sai Prestige actively provides it. Clearly distinguish referral or coordination assistance from lending, loan approval, or independent financial advice. Never promise approval or a specific interest rate.

Priority localities supplied by the business are Ulwe, Sanpada, Vashi, and Pushpak Nagar. Other localities and specific services should be described only when verified.

It aims to help buyers, sellers, tenants, landlords, and investors navigate property decisions through personalised guidance, transparent communication, and practical information. Sai Prestige provides real estate consultancy assistance in selected Navi Mumbai localities, including Ulwe, Sanpada, Vashi, and Pushpak Nagar. Contact the team to discuss buying, selling, rental, or property-evaluation requirements and confirm current availability.

### GEO publishing checklist
- Publish a complete About page with consistent brand identity and verified contact details.
- Explain each service in plain language, including limitations.
- Publish useful local guides supported by credible, current sources.
- Put important information in crawlable HTML text, not only in images or client-side interactions.

- Attribute statistics, infrastructure claims, legal requirements, and market information to trustworthy sources and dates.
- Show author/reviewer details when genuine and useful; do not invent credentials.

## 11. Structured data guidance

Structured data helps machines interpret page information; it does not guarantee a rich result or higher ranking.

### Organization / LocalBusiness
Choose the most accurate Schema.org type based on the actual business. `RealEstateAgent` may be appropriate if the business genuinely operates as a real estate agency/agent. Do not automatically use multiple overlapping business types. Include only verified values:
- `name`
- `url`
- `logo`
- `image`
- `telephone`
- `email`
- `address` (only if accurate and public)
- `areaServed` (only actual service areas)
- `openingHoursSpecification` (only confirmed hours)
- `sameAs` (official social profiles only)

Do not invent a street address, map coordinates, price range, ratings, or reviews. If the business is a service-area business without a public customer-facing office, configure its business profile and schema accordingly rather than exposing a private address.

### WebSite
Add site-level metadata and a canonical domain. A `SearchAction` should only be included if the website actually provides a functioning search experience.

### BreadcrumbList
Use for meaningful nested pages, such as Home → Locations → Ulwe or Home → Services → Buying Assistance.

### Article / BlogPosting
Use for editorial guides. Include a real headline, accurate publication and modification dates, author information when known, and the correct canonical URL. Keep schema consistent with visible content.

### Product / Offer / RealEstateListing
Do not mark up consultancy services as individual property listings. Use listing or offer markup only when supported by the actual content, correct property data, and applicable schema requirements. Keep price, availability, and status current.

### Review / AggregateRating
Use only eligible, authentic reviews that meet search engine policies. Never generate fake reviews or self-serving review markup to imply ratings that do not exist.

### FAQPage
FAQs can help readers and provide clear content structure, but FAQ rich results are limited by current search engine policies. Do not promise a special search display. Keep FAQs visible and useful.

### Implementation requirements
- Generate structured data from the same verified data source as visible page content.
- Validate JSON-LD syntax and test using Google's Rich Results Test where applicable and Schema.org Validator.
- Avoid contradictory schema on the homepage and location pages.
- Never add fabricated fields just to fill a schema template.
- Re-check schema whenever contact details, service areas, inventory, or business details change.

## 12. Technical SEO checklist for Next.js

### Crawlability and indexing
- Use stable, readable URLs.
- Render essential page content in crawlable HTML.
- Configure `metadata` or `generateMetadata` for unique titles, descriptions, canonical URLs, Open Graph tags, and social sharing metadata.
- Generate `/sitemap.xml` using Next.js sitemap support.
- Configure `/robots.txt` deliberately; do not accidentally block important public pages.
- Set the production canonical domain and redirect alternate hostnames and HTTP to the chosen HTTPS URL.
- Use appropriate status codes: `200` for valid pages, `301` for permanent redirects, and `404`/`410` for removed pages as appropriate.
- Use `noindex` for internal search results, private pages, staging, and other pages that should not appear in search.
- Do not block the assets needed to render important pages.
- Keep development/staging sites out of public indexing.

### Page experience and performance
- Optimize images with Next.js Image where appropriate.
- Use modern image formats when supported and preserve useful image quality.
- Provide descriptive alt text for informative images; use empty alt text for purely decorative images.
- Specify image dimensions to reduce layout shifts.
- Minimize unnecessary JavaScript and third-party scripts.
- Avoid heavy animation that blocks content, interaction, or mobile performance.
- Use responsive layouts and accessible contrast, labels, keyboard navigation, and focus states.
- Monitor Core Web Vitals: LCP, INP, and CLS.
- Test on mid-range Android devices and typical mobile connections, not only a high-end desktop.

### Metadata and social sharing
- Unique title and meta description for each indexable page.
- One clear primary H1 per page as a practical editorial convention.
- Open Graph title, description, and image that accurately represent the page.
- Canonical URL for each intended indexable page.
- Correct `lang` setting, normally `en-IN` for English-India content.
- Consistent favicon and brand identity.

### Images and property media
- Use only images Sai Prestige owns, licenses, or has permission to publish.
- Name files descriptively where useful, such as `ulwe-residential-property-sai-prestige.webp`.
- Write alt text describing the actual image, not a list of search terms.
- Add captions where they clarify property details.
- For every listing, identify the exact project or property only when confirmed.
- Keep image captions, property status, location, and visible listing details consistent.

### Analytics and monitoring
- Set up Google Search Console for the verified domain.
- Set up analytics with an appropriate privacy notice and consent approach where required.
- Track organic landing pages, enquiries, phone clicks, WhatsApp clicks, form completion, and qualified leads.
- Create a Google Business Profile only if eligible and follow Google's business representation guidelines.
- Use Bing Webmaster Tools where appropriate.
- Review indexing, sitemap status, broken links, redirects, and Core Web Vitals periodically.
